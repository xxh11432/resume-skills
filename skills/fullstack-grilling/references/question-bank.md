# 全栈拷打题库

按候选人简历挑题。每条链按 L1→L4 顺序问，答不上就停在那层，记为漏洞，不要跳层。
题库只提供方向；具体问题必须从简历里的项目和技能自然延伸出来。

## 一、项目拷打模板

任何一段全栈项目，先做三件事：定位真实职责、量化、找破绽。

**定位**
- 这个产品谁在用？上线了吗？日活 / 用户量多少？
- 你一个人做的还是团队？前端、后端、部署分别谁负责？
- 需求是谁提的？你在需求阶段改过什么、砍过什么？
- 为什么做 Web，而不是小程序或桌面端？

**量化**
- 核心页面首屏和交互延迟多少？接口 P95 多少？
- 数据量多大？多少张表？多少并发？
- 上线后转化、留存或使用时长有变化吗？

**找破绽**（挑一个往下压）
- 你说独立完成，部署和域名谁弄的？线上出问题谁修？
- 接口是 REST 还是 RPC？为什么？
- 前后端状态怎么同步？刷新页面会丢什么？
- 这套设计有没有你当时就知道的坑，但没时间改？

## 二、需求与产品判断

- L1：核心用户是谁？最常用的一条路径是什么？
- L2：为什么先做这个功能？砍掉了什么？
- L3：空态、加载态、错误态分别怎么设计？
- L4：用户量涨 10 倍，产品上先改什么？

- L4：首屏 4 秒，怎么定位是网络、JS、渲染还是接口？优化顺序是什么？

- L1：路由怎么组织？权限路由怎么做？

- L3：水合不一致会怎样？怎么排查？

- L1：请求怎么封装的？

- L3：乐观更新失败怎么回滚？

- L1：移动端怎么适配？
- L2：响应式断点怎么定？
- L3：移动端键盘弹起、滚动穿透怎么处理？
- L4：同一套代码要兼容桌面和移动，哪些地方必须分叉？

- L1：打包工具是什么？构建多久？

- L1：鉴权用的什么？token 存哪？

- L3：越权怎么防？水平越权和垂直越权分别在哪校验？

- L1：有没有幂等要求？

- L3：幂等键存哪、存多久？服务重启会怎样？
- L4：支付或下单回调重复到达，怎么保证只生效一次？

- L1：分页怎么做的？
- L2：深分页怎么优化？
- L3：列表筛选条件多，索引怎么建？
- L4：列表要支持任意字段排序，数据库扛不住怎么办？

- L3：事务边界在哪？跨表操作怎么保证一致？
- L4：数据量到 1000 万，先加索引还是先分表？判断依据是什么？

- L1：缓存了什么？
- L2：缓存 key 怎么设计？过期时间怎么定？
- L3：缓存和数据库不一致怎么处理？

- L1：有没有文件上传？

## 六、安全

- XSS 有哪几类？React 的 dangerouslySetInnerHTML 什么时候能用？
- CSRF 怎么发生？SameSite、token、校验 Origin 各解决什么？
- CORS 预检什么时候触发？credentials 模式下 origin 能写 * 吗？
- 密钥放前端会怎样？环境变量怎么管理？
- 用户输入直接拼 SQL 会怎样？ORM 就一定安全吗？
- 依赖漏洞怎么发现和升级？

- L1：怎么部署？域名、HTTPS、Nginx 配置谁写的？

- L3：发布过程用户会看到什么？怎么做到不停机？
- L4：回滚怎么做？数据库迁移回滚不了怎么办？

- L1：日志在哪看？
- L2：线上 500 怎么定位？前后端怎么分工排查？
- L3：前端白屏怎么发现？sourcemap 怎么用？
- L4：接口 P95 从 100ms 涨到 2s，前端能做什么、后端该做什么？

- L1：服务器什么配置？一个月多少钱？
- L2：静态资源怎么缓存？CDN 怎么配？

## 八、场景题（二选一）

**A. 线上故障排查**
- 用户反馈打开首页白屏，部分用户正常。你手上只有监控、日志和错误上报，前 20 分钟怎么排查？按顺序说看什么、判断依据是什么。
- 下单接口偶发 500，前端提示「网络错误」。怎么判断是前端、网关、后端还是数据库的问题？
- 发版后部分用户一直加载旧页面，刷新才好。原因可能是什么？怎么修？

**B. 从 0 交付**
- 给你一个「团队周报」需求，两周上线，只有你一个人。说清你会怎么拆：页面、接口、数据表、鉴权、部署，以及第一版砍掉什么。
- 现有后台系统要加一个「导出 Excel」功能，数据 10 万行。前后端方案怎么设计？同步还是异步？失败了怎么通知？

## 九、杀招（收尾用，任选一个）

- 你说独立完成，哪部分是你最不熟的？当时怎么补的？
- 这个项目如果明天要加一个前端同事，你的代码他能接手吗？哪里会卡住他？
- 你做的功能里，哪个上线后发现用户根本不用？为什么？
- 如果预算只有一台 2C2G 服务器，你这套东西怎么上线？
- 你最后悔的一个技术决策是什么？
