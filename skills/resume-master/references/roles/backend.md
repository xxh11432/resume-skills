# 后端开发岗：版本写法

## 一、HR 和前 10 秒在找什么

后端简历先证明四件事，顺序不要反：

1. **业务复杂度**：不是 CRUD 练习，而是真实约束下的系统。
2. **正确性**：并发、事务、幂等、一致性，出了边界情况还能不能对。
3. **稳定性与性能**：流量、故障、延迟、容量，有没有非功能指标。
4. **工程判断**：为什么选 A 不选 B，代价是什么，怎么监控和回滚。

学历和年限是门槛，项目和非功能指标才是区分度。

## 二、模块顺序

默认顺序：

1. 个人信息（姓名、电话、邮箱、GitHub、城市/意向）
2. 求职意向（岗位名称 + 年限/届别）
3. 教育经历
4. 技术栈
5. 工作 / 实习经历
6. 项目经历
7. 其他（开源、博客、竞赛、证书）

校招可把教育前移；社招把工作经历前移；技术栈放在教育后或工作前都可以，但不要占太大篇幅。

## 三、项目条目怎么写

每条项目按「四层」组织：

| 层 | 写什么 | 示例 |
|---|---|---|
| 场景 | 一句话说明规模和约束 | 面向 3 万日活的订单系统，峰值 1200 QPS |
| 难点 | 最容易坏在哪 | 支付回调重复、库存超卖、热点 key |
| 机制 | 用户具体做了什么 | 本地消息表、幂等键、分布式锁、多级缓存 |
| 结果 | 指标或可验证变化 | 不一致率 0.3% → 0.01%，P99 800ms → 220ms |

推荐 2-4 条 bullet，第一条给架构/职责，后面给机制和结果。不要把每个技术点都写成一条。

### 可直接套用的句式

- `负责 <strong>XX 模块</strong>，基于 <strong>XX 架构/机制</strong> 解决 <strong>XX 问题</strong>，支撑 <strong>XX 规模</strong>。`
- `针对 <strong>XX 场景</strong>，用 <strong>XX 方案</strong> 替代 <strong>XX 方案</strong>，将 <strong>XX 指标</strong> 从 A 优化到 B。`
- `设计 <strong>XX 机制</strong>，覆盖 <strong>XX 异常/边界</strong>，线上 <strong>XX 指标</strong> 保持稳定。`
- `重构 <strong>XX 链路</strong>，拆分 <strong>XX 职责</strong>，降低 <strong>XX 耦合/延迟/成本</strong>。`

## 四、技术栈怎么排

只写真实用过的。按「语言 → 框架 → 存储 → 中间件 → 部署/观测」分组，比一长串逗号列表更易扫读。

示例分组：

- **语言**：Java 17、Go、Python（按岗位主语言放第一位）
- **框架**：Spring Boot、Spring Cloud、MyBatis
- **存储**：MySQL、Redis、Elasticsearch
- **中间件**：RocketMQ / Kafka
- **工程**：Docker、Kubernetes、GitHub Actions、Prometheus + Grafana

不要写「精通」除非能被追问三层；不确定的写「熟悉 / 使用过」。

## 五、不同技术栈的重心

| 栈 | 项目里优先出现 | 容易加分的证据 |
|---|---|---|
| Java | Spring Boot、JVM、GC、线程池、事务、MyBatis | 压测、GC 日志、慢查询、故障排查 |
| Go | GMP、goroutine、channel、pprof、etcd | 高并发服务、内存/协程泄漏排查 |
| Python | FastAPI/Django、异步、Celery、数据处理 | 接口性能、任务编排、数据管道 |

语言只是入口，后端岗最终看的是「系统怎么坏、你怎么防」。

## 六、校招 vs 社招

- **校招**：项目可以小，但要有完整闭环和非功能思考；实习经历优先写真实线上系统。
- **1-3 年**：突出独立负责模块、排查过的问题、做过的取舍；至少一个可量化结果。
- **3-5 年**：突出系统设计、跨团队协作、容量规划、稳定性建设；减少「参与」，增加「负责/主导/推动」。

## 七、常见误区

1. **只有业务功能，没有非功能指标**：写了订单、用户、权限，却没有 QPS、延迟、数据量、故障处理。
2. **技术栈堆砌**：列了 20 个名词，项目里一个都没落地。
3. **把团队成果写成个人成果**：没有边界，面试一追问就露馅。
4. **只写「优化」不写前后对比**：优化是结论，不是证据。
5. **所有项目都写「高并发」**：没有规模数据，高并发就是形容词。
6. **把课程项目写成生产系统**：上线、用户、监控一个都没有。

## 八、交付前自检

- [ ] 至少一个项目有明确的规模数字或约束
- [ ] 至少一条 bullet 能讲清「为什么选这个方案」
- [ ] 至少一条 bullet 涉及异常、边界或故障处理
- [ ] 技术栈里的每项都能在项目中找到落点
- [ ] 没有把「参与」写成「主导」
- [ ] 面试官按 backend-grilling 的三层追问（现象 → 机制 → 边界），简历站得住
