# 全栈开发岗：版本写法

## 一、HR 和前 10 秒在找什么

全栈不是「前端也会、后端也会」，而是**能独立把一件事做完**。简历要先证明：

1. **端到端闭环**：需求 → 界面 → 接口 → 数据 → 上线，至少有一个完整项目。
2. **产品感**：知道用户怎么用，能处理加载、空态、错误、移动端。
3. **接口与数据设计**：前后端契约清楚，不是前端随便调、后端随便返回。
4. **交付能力**：部署、监控、回滚，不是只会在本地跑。

只写「熟悉 React 和 Spring Boot」没有说服力，要写「我一个人把什么做上线了」。

## 二、模块顺序

默认顺序：

1. 个人信息
2. 求职意向
3. 项目经历（全栈岗可前移到教育之前）
4. 技术栈
5. 工作 / 实习经历
6. 教育经历
7. 其他

项目是全栈岗的主证据，不要让教育和技术栈占掉上半页。

## 三、项目条目怎么写

一段全栈项目要覆盖五个环节，但不必平均用力：

| 环节 | 写什么 | 例子 |
|---|---|---|
| 需求 | 谁用、解决什么问题 | 面向小团队的周报协作工具 |
| 前端 | 页面、交互、状态、响应式 | React + SSE 流式输出、移动端适配 |
| 接口 | 契约、鉴权、错误处理 | REST + zod 校验、统一错误码 |
| 数据 | 建模、索引、缓存 | PostgreSQL + Prisma、关键查询加索引 |
| 交付 | 部署、监控、成本 | Docker Compose + Nginx、健康检查 |

推荐 3-4 条 bullet，第一条写「从 0 到 1 / 独立交付」，后面挑 2-3 个最能证明深度的环节。

### 可直接套用的句式

- `独立完成 <strong>XX 产品</strong> 从需求到上线，前端用 <strong>XX</strong>，后端用 <strong>XX</strong>，支撑 <strong>XX 用户/XX 数据量</strong>。`
- `设计 <strong>XX API 契约</strong> 与 <strong>XX 状态管理</strong>，把 <strong>XX 重复请求/状态错乱</strong> 收敛为一套流程。`
- `优化 <strong>XX 页面</strong> 的首屏与交互，<strong>Lighthouse 从 A 到 B</strong>，核心操作路径缩短 <strong>XX</strong>。`
- `用 <strong>Docker + Nginx + CI</strong> 完成一键部署，把发布耗时从 <strong>XX 分钟降到 XX 分钟</strong>。`

## 四、技术栈怎么排

按「前端 → 后端 → 数据 → 交付」四组，确保每组都有项目落点。

| 组 | 常见项 |
|---|---|
| 前端 | TypeScript、React / Next.js、Vue / Nuxt、Tailwind CSS、shadcn/ui |
| 后端 | Node.js / NestJS、Java / Spring Boot、Python / FastAPI |
| 数据 | PostgreSQL、MySQL、Redis、Prisma / MyBatis |
| 交付 | Docker、Nginx、GitHub Actions、Vercel、监控与日志 |

写法示例：

- **前端**：TypeScript、React、Next.js、Tailwind CSS
- **后端**：Node.js、NestJS、REST API、SSE
- **数据**：PostgreSQL、Prisma、Redis
- **交付**：Docker、Nginx、GitHub Actions

## 五、三种全栈路径

| 路径 | 典型组合 | 简历重心 |
|---|---|---|
| 前端主导 | Next.js + Node/Server Actions | 交互、性能、组件化、SSR |
| 后端主导 | Vue/React + Java/Go | 接口设计、权限、数据一致性 |
| 独立产品 | Next.js + FastAPI/Node + 云部署 | 端到端闭环、上线、用户反馈 |

不要假装三条都精通。选一条主路径，其他作为补充。

## 六、校招 vs 社招

- **校招**：一个完整上线的个人项目 + 一个团队项目足够；强调独立解决问题和产品思考。
- **1-3 年**：突出负责的完整模块或子系统，能讲清前后端如何协作。
- **3-5 年**：突出架构取舍、性能与稳定性、跨端/跨团队协作；减少页面细节。

## 七、常见误区

1. **前后端各写一半，谁也不深**：至少有一个环节能讲到机制和边界。
2. **只写页面，不写接口和数据**：那是前端简历，不是全栈。
3. **只写技术栈，不写交付**：没有上线、部署、监控，端到端不成立。
4. **所有项目都写「独立开发」**：团队项目要写清边界。
5. **把 UI 截图当成果**：截图是证据，结果要有指标或用户反馈。
6. **忽略异常态**：加载、空数据、失败重试、移动端，才是产品完成度。

## 八、交付前自检

- [ ] 至少一个项目覆盖需求 → 前端 → 接口 → 数据 → 上线
- [ ] 有一个环节能讲到实现机制，而不是只报框架名
- [ ] 技术栈四组都有项目落点
- [ ] 写了至少一个产品/交互层面的判断
- [ ] 有部署或运维证据
- [ ] 没有把前端实习写成全栈主导
