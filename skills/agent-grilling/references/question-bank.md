# Agent 拷打题库

按候选人简历挑题。每条链按 L1→L4 顺序问，答不上就停在那层，记为漏洞，不要跳层。
题库只提供方向；具体问题必须从简历里的项目和技能自然延伸出来。

## 一、项目拷打模板

任何一段 Agent 项目，先做三件事：定位真实职责、量化、找破绽。

**定位**
- 这个 Agent 上线了吗？谁在用？每天多少请求、多少用户？
- 你负责哪几块：数据、检索、编排、评估、前端？团队几个人？
- 上下游分别是谁：文档源、业务系统、模型供应商？
- 为什么这个需求要做成 Agent，不做成表单或规则？

**量化**
- 成功率 / 采纳率 / 人工转接率是多少？怎么统计的？
- 评估集多少条？线上 P95 延迟、单次 token 成本多少？
- 上线前后指标变化多少？你负责的部分贡献了多少？

**找破绽**（挑一个往下压）
- 你说准确率 85%，分母是什么？谁判的对错？
- 你说用了 RAG，召回率多少？没召回的时候怎么办？
- 你说接了工具，工具报错、超时、参数错，链路会怎么走？
- 这套设计有没有你当时就知道的坑，但没时间改？

## 二、RAG 全链路

- L1：知识库多大？多少文档、多少 chunk？更新频率？
- L2：解析怎么做的？PDF 表格和图片怎么处理？chunk 大小和重叠怎么定？
- L3：召回为什么用向量 / BM25 / 混合？换 embedding 模型后旧索引怎么办？
- L4：召回率上不去，怎么定位是解析、切分、embedding 还是 query 改写的问题？

- L1：用了 rerank 吗？为什么？
- L2：粗排召回多少条、精排留多少条？上下文塞多少 token？
- L3：长文档跨 chunk 的问题怎么解决？父子块、滑窗、摘要各解决什么？
- L4：用户问「上季度的总额」，需要跨多文档聚合，RAG 怎么处理？答不了怎么办？

- L1：引用怎么做的？引用能点开吗？
- L2：怎么保证引用和答案对应？模型编造引用怎么发现？
- L3：检索为空时返回什么？让模型自由发挥还是明确说不知道？
- L4：知识库里有互相冲突的两份文档，怎么让答案稳定？

## 三、工具调用与编排

- L1：一共几个工具？谁定义 schema？
- L2：function calling 的入参怎么校验？模型给了不存在的方法怎么办？
- L3：工具执行到一半失败，已产生的副作用怎么回滚？重试会不会重复扣款？
- L4：多步任务里，第 3 步发现前面参数错了，怎么中断和重规划？状态存哪？

- L1：单 Agent 还是多 Agent？为什么？
- L2：编排用代码、状态机还是模型自主规划？边界在哪？
- L3：模型自主规划跑飞了怎么止损？最大步数、超时、预算怎么设？
- L4：为什么不用固定 workflow？多出来的不确定性换来了什么？

- L1：记忆存什么？存多久？
- L2：短期上下文怎么裁剪？长期记忆怎么检索和更新？
- L3：记忆错了或过期了怎么纠正？会不会把错误越记越深？
- L4：多轮任务中断后恢复，怎么保证上下文一致？

- L1：MCP 用过吗？接了什么 server？
- L2：MCP 工具的权限边界怎么控制？谁批准高风险操作？
- L3：工具返回超大结果怎么处理？直接塞上下文会怎样？
- L4：接入第三方 MCP server，怎么防提示注入和越权调用？

## 四、评估体系

- L1：有没有评估集？多少条？
- L2：评估集怎么构造：真实日志、人工编写、模型生成？比例多少？
- L3：谁标的？标注一致性怎么保证？有争议的样本怎么处理？
- L4：线上分布变了，评估集怎么更新？怎么防止评估集污染和过拟合？

- L1：用什么指标？准确率、召回、引用命中、任务完成率？
- L2：LLM-as-judge 怎么设计 prompt？judge 本身不可靠怎么办？
- L3：离线涨了 5 个点，线上没变化，可能是什么原因？
- L4：两个版本各有胜负，怎么决定上线哪个？置信度怎么算？

- L1：改 prompt 之后怎么回归？
- L2：回归跑多少条？跑一次多久、多少钱？
- L3：怎么防止修好 A 类问题、弄坏 B 类问题？
- L4：模型供应商升级或下线旧模型，怎么评估迁移风险？

- L3：few-shot 示例怎么选？示例冲突怎么办？
- L4：prompt 越加越长，为什么效果反而变差？怎么取舍？

- L1：上下文窗口多大？实际用多少？
- L2：长上下文和 RAG 怎么选？
- L3：中间内容被忽略（lost in the middle）怎么缓解？
- L4：上下文里混入用户上传的恶意指令，怎么防？

## 六、延迟、成本与并发

- L1：P95 延迟多少？一次请求几个模型调用？
- L2：延迟主要花在哪：检索、首 token、生成、工具？怎么测的？
- L3：流式输出解决了什么、没解决什么？首 token 慢怎么优化？
- L4：高峰期模型限流 429，怎么排队、降级、切模型？用户会看到什么？

- L1：单次请求 token 成本多少？一个月多少钱？
- L2：成本大头在哪：输入、输出、检索、rerank？
- L3：哪些请求可以走小模型？路由错了怎么办？
- L4：成本要降 50%，但准确率不能掉超过 2 个点，你会动哪里？

- L1：并发多少？怎么限流？
- L2：同步还是异步？长任务怎么处理？
- L3：同一用户重复提交怎么去重？幂等键放哪？
- L4：批量跑 10 万条评估，怎么控制并发和费用？

## 七、失败兜底与安全

- L1：模型超时会怎样？
- L2：重试策略怎么定？重试会放大下游压力吗？
- L3：模型连续返回非法 JSON，链路怎么终止？
- L4：模型自信地胡说，怎么在系统层发现并拦截？

- L1：有没有权限控制？
- L2：用户 A 能不能通过提问拿到用户 B 的数据？怎么防？
- L3：提示注入有哪几类？工具型 Agent 和知识库型分别怎么防？
- L4：高风险动作（转账、删数据、发邮件）怎么设计人工确认与审计？

## 八、可观测性与线上迭代

- L1：线上记录什么？日志里存 prompt 和回答吗？
- L2：怎么追踪一次请求的完整链路和 token 消耗？
- L3：用户点踩之后，怎么定位是检索错、上下文缺、还是模型没按格式？
- L4：怎么做 A/B？分流维度是什么？指标多久能看出来？

## 九、场景题（二选一）

**A. 效果退化排查**
- 周一来发现知识库问答准确率从 82% 掉到 61%，模型和代码都没发版。前 30 分钟你怎么排查？按顺序说看什么、判断依据是什么。
- 用户反馈「最近答非所问」，但监控没报警。你怎么把问题量化出来？

**B. 延迟与成本优化**
- P95 延迟 8 秒、单次成本 0.3 元，产品要求 3 秒、0.1 元，准确率不能掉。你按什么顺序优化？每一步的预期收益和风险是什么？
- 流量涨 5 倍，模型供应商限流不变。怎么设计排队、降级和缓存？哪些请求可以拒绝？

## 十、杀招（收尾用，任选一个）

- 你怎么证明你的 Agent 比一个「搜索 + 大模型总结」的简单方案更好？
- 你最近一次评估结果和线上表现不一致，是什么原因？
- 你的评估集里，最让你不安的一条是什么？
- 如果模型能力明天提升一大截，你这套系统里哪部分会变得没价值？
- 你最后悔的一个技术决策是什么？
